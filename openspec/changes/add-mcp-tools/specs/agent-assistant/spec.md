## MODIFIED Requirements

### Requirement: 多轮会话与上下文延续
学生 MUST 能创建并连续追问多个会话，历史作为有限轮数上下文。会话 MUST 归属本人和当前班级；读取、删除、追问他人或跨班会话 MUST 统一返回 404，与不存在资源一致，MUST NOT 泄露归属。

#### Scenario: 连续追问
- **WHEN** 学生在本人当前班级会话连续提问
- **THEN** 系统带入最近有限轮数历史并延续前文

#### Scenario: 非本人和跨班统一不可见
- **WHEN** 学生读取、删除或追问他人、跨班或不存在会话
- **THEN** 均返回 404，不调用 MCP 或大模型

### Requirement: SSE 流式回答
对话 MUST 保留 delta/done/error 兼容性，并通过 meta 与 done 携带 tool_calls。工具结果 MUST 作为当前用户消息的数据上下文，工具失败不阻断原 RAG/回答。无模型密钥时 MUST 展示成功工具结果及资料，MUST NOT 声明未执行工具已成功。

#### Scenario: 工具辅助回答
- **WHEN** 对话触发已绑定 MCP 工具
- **THEN** 先发含调用状态的 meta，再发回答 delta/done，done 和历史消息保留相同 tool_calls

#### Scenario: 模型不可用仍保留工具结果
- **WHEN** MCP 工具成功但大模型未配置或调用失败
- **THEN** 输出成功工具文本与可用资料，并持久化调用元数据

## ADDED Requirements

### Requirement: 自然天气提问与会话内补参
启用本班天气技能时系统 MUST 识别天气、下雨、带伞、冷不冷等常见天气意图，不要求精确触发词。缺少地点时 MUST 以 needs_input 请求补充并保留日期窗口；未调用远端工具时 MUST NOT 记录成功或失败调用审计。当前会话最近有限轮内，单独补充地名、追问明天 MUST 能继续天气任务。上下文 MUST NOT 跨会话或跨班复用，调用前仍 MUST 校验本班连接和发现缓存。

#### Scenario: 缺少地点后补充区县
- **WHEN** 学生问“今天的天气怎么样”，随后在同会话回复“北京市大兴区”
- **THEN** 第一轮询问地点并显示“请补充地点”，第二轮调用本班 weather_query，保留今天的查询范围

#### Scenario: 自然问法与日期追问
- **WHEN** 学生问“请帮我看看北京明天会下雨吗”或“我在北京市大兴区，今天要带伞吗”，随后追问“那明天呢”
- **THEN** 系统提取地点及日期，不要求用户提供工具参数名；日期追问沿用同会话地点

#### Scenario: 补参期间断开
- **WHEN** 等待地点期间教师断开服务，学生再补充地点
- **THEN** 不执行远端调用，状态为 denied，审计记录拒绝

### Requirement: 天气事实与数学公式展示
仅天气工具结果的回答 MUST 直接格式化供应商事实及来源，不得受“班级资料未找到”提示干扰；单位 MUST 使用普通 °C、%、km/h 文本。数学答案 MUST 支持 $/$$ 与标准 LaTeX 行内、块级定界符，MUST 保留代码示例原文。

#### Scenario: 天气无需知识库材料
- **WHEN** 本班没有天气学习材料，天气工具成功返回温度与湿度
- **THEN** 回答显示真实天气和普通单位，不出现无关的资料缺失说明

#### Scenario: 带空格的温度公式
- **WHEN** 历史或新答案包含标准行内温度公式、分式与块级向量公式
- **THEN** KaTeX 正常渲染，无 katex-error；代码中的定界符保持原样
